## 1. 先选择正确场景

| 场景 | 入口 | 数据／媒体 |
| --- | --- | --- |
| 离线讲解 | 微信编译页面 `pagesSub/live/lobby`，参数 `mode=demo` | 虚构本地数据，13个可切换人物；无网络／真实身份写入 |

普通入口失败不会退回 Demo。不要修改全局 `USE_MOCK` 或写假 Token。前端既有 API 地址在 `api/config.uts`，本机默认127.0.0.1:8000；使用目标测试服务时按项目配置规则处理，不擅自覆盖正式地址。

## 3. 多账号操作手册

### 运营：准备与名单

- 使用被授权的平台管理员测试账号。大厅点“创建与安排场次”，填写未来时间、标题及明确“本次不采集音视频”的展示告知。
- 在“搜索账号并分配席位”选择目标角色，输入昵称或账号ID，点“搜索现有账号”和“加入主持／红娘／男嘉宾／女嘉宾／观众”。资格缺项会显示，重复人员和组别错误不能使用。运营本人不占任何席位。
- 主持1、红娘2、男4、女4，选择不重复的2男2女作为四轮主嘉宾；观众可0—20人。嘉宾加入顺序就是候选席顺序。点“创建草稿并检查名单”，进入房间后“确认排期”。
- 未开场可点“修改场次与名单”，编辑后“保存场次与名单”。时间／告知改动使全员重新确认；角色／席位／轮序改动使受影响者重新确认与签到。不能把这些重置当故障而直接修改数据库放行。

### 主持、红娘与嘉宾：邀请及签到

- 从站内“通知”打开直播邀请，或从直播大厅进入。确认本人本场角色，填写公开称呼／介绍，阅读告知后独立确认；也可以点“拒绝本次邀请”。预约观看是另一项记录，不等于确认上台。
- 无媒体场次点“业务签到（无音视频）”，候场页明确“未执行音视频检测”，再点“确认签到”；不会索取摄像头或麦克风权限，也没有设备通过记录。
- 主持在11位互动人员确认签到后点“开始业务演练”。红娘没有该按钮；观众也不能发起嘉宾动作。其余工作人员、嘉宾和观众分别用自己的登录设备／会话验证。

### 控场、四轮与异常

- 当前有效控场者用“推进下一环节”“暂停流程”“恢复流程”“延长 1 分钟”。介绍→问答→亮灯→私密选择→依次交流→轮换；正式接口不提供跳过选择／交流等待，自动测试只在服务端测试夹具中推进时钟。
- 红娘在问答阶段申请／撤回提问，本轮候选人申请／撤回发言；主持展开“查看名单与人员操作”，对允许对象点“请TA发言”。候场嘉宾本轮不举手。所有按钮来自服务端 `allowed_actions` 和 `allowed_targets`，不是客户端永久账号身份。
- 运营“接管主持流程”填写原因后成为唯一控场者，原主持不能再推进或安排发言；“交还主持”也填写原因，且主持必须在场。接管不自动上台、不代亮灯选择。
- 暂停停止新选择和推进，允许退出、离场、撤回公开意向。主嘉宾明确离场后，控场者点“主嘉宾已离场，确认跳轮”并记录原因。断网不会自动触发离场或接管。
- 私密选择只发本人意愿；截止后只公布互选，按候选席顺序交流。无人互选直接轮换，没有替代配对。特别心动每场一次，撤回不恢复，不改变选择与顺序。
- 工作人员可“查看操作记录”；仅本场主持／运营处理举报，红娘只能提问、举报和查看脱敏记录。主持不能移出运营。其他管理员不能通过场次ID进入不属于自己的场次。

### 场后

- 有效控场者或本场运营结束场次后，参与者收到结果通知，进入“本人场后结果”。每对已完成交流者共享一次免费机会，结束后72小时有效，不自动发申请。
- 点“使用免费机会申请认识”，确认后沿用现有申请系统；“前往消息查看申请”，接收方独立同意／拒绝。只有同意后才能进入原聊天。用完日常次数不影响免费机会，但实名、资料、封禁、拉黑和关系限制仍生效。
- 重复／双方同时发送只能形成同一有效申请；拒绝不恢复机会、不退日常次数。被移出不抹掉已经完成的交流与机会，不新增场后惩罚。

## 4. 前后端维护分工

| 位置 | 职责 |
| --- | --- |
| api/live-v2.uts | UTS契约、真实HTTP、账号隔离与WS；新增搜索／更新／分页日志 |
| pagesSub/live/client.uts | 只按显式Demo参数选本地或真实传输，不做失败回退 |
| pagesSub/live/LiveRosterEditor.uvue、manage.uvue | 搜索选人、组别／席位、四轮顺序、版本编辑；只显示基础身份信息 |
| LiveStaffPanel.uvue、LiveRoundActions.uvue | 有效动作和目标范围、接管弹层、私密草稿；失去控场权／切号后销毁旧状态 |
| backstage.uvue、room.uvue | 媒体模式标识；只有非Demo且trtc才挂载真实音视频组件 |
| results.uvue | 本人机会与既有申请；旧账号确认框或卸载后的回调不会提交 |
| pagesSub/community/notifications.uvue | 直播通知转到详情；live_result转本人结果，不把旧通知当权限凭证 |
| demo.uts、LiveDemoPanel.uvue | 运营编号13、独立控场规则、本地选择与场后演示；不连真实选人 |
| 后端 live_permissions / live_domain / live / live_media | 统一权限／纯业务转换／事务和实时／云媒体边界 |

没有新增通用权限平台、工作流引擎、前端密钥输入框、后端数据表或项目依赖。小场次仍用既有MySQL聚合；Redis只通知版本，各账号再取自己的快照。版本冲突明确报错刷新，不静默重试选择。详细字段以自动导出的后端接口为准。

UTS编译会把未填写的可选类型字段初始化为null。`sendLiveCommand`在HTTP边界显式组装命令，只发送非空的可选字段；有意提交的空数组与false必须保留，不能用真假过滤。后端仍按严格Pydantic模型校验，不放宽为任意null。该差异已通过实际微信排期请求复现，并有源码回归。
