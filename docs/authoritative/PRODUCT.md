# 宣誓爱 — 产品定义

> **版本：** 2.4.0\
> **更新日期：** 2026-09-05\
> **当前形态：** UniApp 前端应用（H5 / 微信小程序）\
> **产品阶段：** 社区 1.0 已接测试服；其它产品域仍处于分模块联调阶段\
> **需求状态：** 定版 PRD 已登记；范围与付费边界以决策层为准

## Product Summary

宣誓爱是一款面向认真婚恋人群的中文移动产品。它不追求快速滑动、即时刺激和无限骚扰式私信，而是通过真实资料、认证体系、故事化人物展示、关系期待、申请认识、双方同意和专业牵线，帮助用户在可信、安全、有边界的环境中建立长期关系。

产品体验主轴：

> **从故事认识，到信任行动。**

### 社区 1.0 基线

本版本将社区浏览、筛选、话题、活动、通知、纸飞机、互动、详情与评论作为第一阶段验收范围。微信小程序端以 HBuilderX 生成的 `mp-weixin` 产物为准，开发期使用本机 FastAPI 和数据库种子数据验证；本地 DevTools 通过不等于物理真机、正式 HTTPS 合法域名或生产发布完成。

- **Story / 故事：** 照片只负责第一眼，自我介绍、声音、生活切片和关系期待负责理解。
- **Trust / 信任：** 认证状态在关键决策前提供可核验信息；**双重认证**定义为 **实名通过 + 学历人工审核通过**。
- **Action / 行动：** 喜欢（私有列表）、申请认识、双方同意、开始聊天，每一步都清晰、克制、可解释。

## Product Promise

宣誓爱向用户承诺：

1. **真实可验证：** 认证状态明确展示，不把未认证、审核中包装成已认证。
2. **目标先对齐：** 在申请认识前展示关系期待、择偶边界和重要资料。
3. **双方有选择：** 对方同意后才开启聊天；拒绝不应造成骚扰或惩罚。
4. **隐私受保护：** 未经同意不展示联系方式，举报、安全提示和数据删除路径易于触达。
5. **付费可理解：** 权益、金额、周期和限制清楚展示，不默认勾选连续包月，不用虚假倒计时催促。
6. **AI 不替人承诺：** AI 合拍度只做资料整理、交集提示和破冰建议，不承诺关系结果。
7. **AI 分身边界清晰：** AI 分身只整理目标用户当前可见的公开资料，必须明确标注为 AI，不冒充本人，也不绕过资料可见性或双方同意门槛。

## Audience and Context

### 核心用户

- 24—38 岁，对长期关系有明确期待的单身用户。
- 主要生活在一二线城市、省会和区域中心城市。
- 有稳定工作或事业规划，重视真实性、边界感和生活质量。
- 对娱乐化交友、虚假资料、无门槛私信和模糊付费保持警惕。

### 典型场景

- 通勤、午休或晚间，单次使用约 15—30 分钟。
- 浏览推荐时快速判断“是否值得继续了解”。
- 阅读档案时认真确认认证、生活方式和关系目标。
- 申请认识时愿意写一句具体、尊重对方的附言。

### 用户首要问题

1. 这个人真实吗？
2. 我能否理解 TA 的生活和性格，而不只是看照片？
3. 我们对长期关系的方向是否接近？
4. 如果我表达兴趣，平台是否保护双方边界？
5. 会员或增值服务是否值得、是否透明？

## Experience Principles

### 1. 阅读优先，而非滑动匹配

首页推荐采用纵向故事流。用户可 **左滑纯浏览换下一个**（不记负反馈）、喜欢或申请认识。**不提供** Tinder 式左右滑动匹配，**删除「不感兴趣」** 负反馈玩法。

### 2. 认证靠近决策点

认证不是装饰徽章。人物卡、完整档案和申请认识前都应能看见认证状态，并能解释认证代表什么、尚未认证 / 审核中代表什么。

### 3. 高价值动作需要上下文

“申请认识”不是随手点赞。确认层需要说明双方同意机制、剩余次数、拒绝规则、隐私保护和附言建议。

### 4. 安全信息前置

聊天开启、线下见面、付费和资料公开范围都要有适时安全提示。不要把安全中心藏在帮助页深处。

### 5. 商业化不破坏信任

付费应提高筛选效率、服务质量或曝光机会，不能以阻断基本安全、制造焦虑或隐藏价格为手段。会员与单次增值（爆灯、置顶、红娘订单）边界清晰。

## Information Architecture

五个一级 Tab（定版顺序，与决策层一致）：

| Tab | 核心内容 | 主要目标 |
|---|---|---|
| **首页** | 推荐故事、广场、筛选、完整档案、AI 合拍度 | 找到值得认真了解的人 |
| **牵线** | 服务红娘、热心红娘、AI 红娘、1v1 / 私人定制 | 获得更主动、更专业的匹配帮助 |
| **社区** | 关注 / 同城 / 发现、话题、发布 | 通过真实生活内容建立侧面理解；关注页「喜欢」展示喜欢用户的动态 |
| **消息** | 申请消息、纸飞机、聊天记录 | 管理关系进展与沟通入口 |
| **我的** | 资料、认证、会员、任务/积分、我的喜欢、我的爆灯、安全与设置 | 完善可信身份并管理账户 |

现有 / 规划二级页面包括：

- 登录、注册、完善资料
- 用户详情、编辑资料
- 聊天详情
- 设置、身份认证、会员中心
- 发布动态
- 我的喜欢、谁看过我 / 我看过谁
- 管理后台（运营侧，见下节边界）

修改五 Tab **顺序或结构**、`pages.json` 核心路由前须明确确认；定版顺序已定为 **首页 / 牵线 / 社区 / 消息 / 我的**，与旧版「首页 / 社区 / 牵线 / …」不同处按决策层收敛实现。

## Core Journeys

### 新用户建立可信档案

```text
登录 / 注册
→ 阅读并同意安全承诺与隐私说明
→ 填写基础资料
→ 上传真实头像
→ 完成实名认证（发布动态另需完成人脸认证）
→ （可选）提交学历认证并等待人工审核通过，通过后计入双重认证展示
→ （可选）头像 / 单身承诺 / 房产 / 婚姻等加分项
→ 补充自我介绍、兴趣和关系期待
→ 进入推荐
```

**双重认证定义（展示层）：** 仅当 **实名已通过** 且 **学历人工审核已通过** 时计为双重；审核中、失败均不算。资料卡与档案可展示双重状态；双重认证 **不作为任何操作门槛**。

**互动门槛（本期实现覆盖）：** 社区浏览无需认证。常规社区互动（点赞 / 关注 / 评论 / 分享 / 活动报名 / 纸飞机）与全局 **申请认识**、**参与话题** 仅要求 **实名通过**；**发布动态（含带话题发布）** 要求 **实名通过 + 人脸通过**。**学历认证仅用于双重认证展示，不作为任何操作门槛。** 举报、拉黑不要求实名。双方同意前仍不得开放聊天或交换联系方式。

### 从推荐到申请认识

```text
查看人物故事
→ 阅读生活切片与关系期待
→ 查看认证与完整档案
→ 喜欢（加入仅自己可见的列表）/ 左滑换下一个 / 爆灯（付费强提醒）
→ 打开申请认识说明
→ 填写具体附言
→ 确认申请（扣当日免费次数或积分加次；不足可引导会员）
→ 等待对方回应
```

### 双方同意后聊天

```text
收到申请 / 查看档案
→ 同意认识
→ 双方确认成功
→ 展示隐私与财产安全提示
→ 开启聊天
```

聊天只能在双方同意后开启。不能通过会员、充值或运营配置绕过这一边界。

### 专业牵线

```text
选择服务红娘 / 热心红娘 / AI 红娘 / 1v1 / 私人定制
→ 了解服务内容、数据使用与价格
→ 提交关系期待
→ 完整在线支付（本期）
→ 接收候选与说明
→ 自主决定是否申请认识
```

红娘或 AI 只能提供建议，不能替用户自动同意、自动发送私信或承诺结果。

### 会员开通（权益拦截路径）

```text
触发会员门槛能力
（如：谁看过我详情、高级筛选上锁项、无痕浏览开关、申请次数用尽后的会员引导）
→ 对比普通用户与会员权益
→ 查看套餐结构（月 / 季 / 年；价格可运营占位）
→ 查看续费方式与退款 / 取消说明
→ 主动选择套餐并确认支付
```

价格和权益以 PRODUCT.md 及运营配置为准。任何页面不得自行创造折扣、倒计时或默认连续包月。

## Trust, Safety and Privacy

### 认证体系

| 项 | 角色 | 说明 |
|---|---|---|
| **实名认证** | 本期互动门槛 | 确认账户对应真实身份。常规社区互动、申请认识、参与话题仅校验实名通过；发布动态另需人脸通过 |
| **人脸认证** | 发布动态门槛；可选展示 | 与实名认证同时通过后方可 **发布动态（含带话题发布）**；资料卡可展示，但 **不计入「双重认证」称谓** |
| **学历认证** | 双重之一（仅展示加分） | 人工审核通过后计入双重展示；**仅作展示，不作为任何操作门槛**；须区分已认证 / 审核中 / 未认证 / 失败 |
| **头像认证** | 可选加分 | 降低盗图、冒用和严重失真风险 |
| **单身承诺书 / 婚姻等** | 可选加分 | **不计入双重**；展示状态时不得伪造已认证 |
| **房产等** | 可选加分 | 同上 |

**称谓边界：** 「双重认证」专指 **实名通过 + 学历人工审核通过**，仅作展示加分；**发布动态** 所需的 **实名 + 人脸** 是独立的发布门槛，不称双重认证，也不在资料卡上合并展示。
学历认证 **不再作为** 参与话题、发布动态或常规社区互动的拦截条件；本条与 §互动门槛 冲突的旧说明以本文件为准。

### 基础安全能力

- 举报与拉黑入口易于触达。
- 用户可以管理资料公开范围，并可申请删除个人数据。
- 不未经同意展示手机号、微信号或其他联系方式。
- 不向第三方出售用户数据。
- 敏感数据遵循最小采集、最小展示和必要授权。

### 社区治理与通知

- 社区点赞、评论、回复和关注可在隐私设置中分别管理站内通知；举报处理、申诉结果和安全处置属于必达站内消息。
- 用户可在设置中查看并解除黑名单。拉黑后双方不得互相浏览社区内容、搜索、关注或发起新的社区互动；解除拉黑不恢复既有关系。
- 举报结论不可被重复覆盖。举报人对被驳回结论、被处置内容的作者对下架结论各可提交一次申诉，复核人不得与原处理人相同。
- 社区评论支持两级展示和回复上下文；用户删除或管理员下架的父评论保留占位，避免其下回复失去上下文。
- 线下见面前提示公共场所见面、告知亲友、警惕财产风险。
- 社区动态卡只提供 **点赞、评论、分享** 三种帖子级互动；帖子不展示收藏/星标动作、收藏数量或收藏状态。
- **我的喜欢** 是用户级、仅自己可见的列表，不作为帖子互动计数，也不向作者或其他用户暴露。
- 社区通知固定分为 **评论、点赞、活动通知** 三类；评论通知覆盖评论、回复和二级回复，并携带 `postId` 与 `commentId`，打开后定位到具体评论。活动通知仅收录官方线下活动的报名、审核、更新、取消、提醒和签到状态；申请认识、系统、安全、举报和红娘消息不进入活动通知。

## Core Interaction Semantics

### 喜欢

- **语义：** 等同原「收藏」能力——点击后加入 **仅自己可见** 的喜欢列表，**不是** 对对方可见的轻意向。
- **入口命名：** 推荐卡与资料页按钮均称 **「喜欢」**；我的页为 **「我的喜欢」**。
- **文案：** 导图或旧稿中的「收藏」对外统一改为「喜欢」。

### 申请认识

- 每日 **免费 3 次**。
- 用尽后：**积分加次**，**也可引导开通会员**；无单独「单次现金购买申请次数」除非另定。
- 对方拒绝不造成骚扰式惩罚；次数规则以确认层说明为准。

### 纸飞机

- 与申请认识 **同构**：每日免费次数（默认 3）+ 积分加次 / 解锁 + 可引导会员。

纸飞机支持文字与语音表达；回复后进入**独立匿名纸飞机聊天页**（可续聊/结束），这与「申请认识 → 双方同意」后的真实私信相互独立，不得互相替代。

脱单纸飞机编辑页在「自我介绍」和「理想的 TA」旁提供可选 **AI 润色**。润色只返回可审阅的候选文案，用户可选择确认替换、复制结果或继续编辑；AI 不得自动替换草稿、自动发出纸飞机或补写用户未提供的事实。

匿名纸飞机聊天页固定提供 **照片、交换微信、交换电话、举报** 四项操作。查看对方头像、申请交换微信或电话前，按“查看者 + 目标用户”隔离的服务端授权检查资料是否已解锁；每个目标用户固定消耗 80 积分。扣减、解锁记录和幂等回放必须在同一原子事务内完成：同一 `Idempotency-Key` 仅能回放同一查看者对同一目标的结果，复用于其他目标必须冲突失败；本人、不可见目标或积分不足均不得解锁。资料解锁后仍不得直接展示微信号或电话号码，联系方式交换必须由双方分别确认。

### 爆灯

- **本期保留**；**5 元/次**。
- 强提醒 + 置顶显示；入口含推荐交互与「我的爆灯」双 Tab。

### 左滑

- **纯浏览换下一个**，不记负反馈；上下滑查看详情。

### 不感兴趣

- **删除**，不与左滑绑定负反馈。

### 会员相关能力（本期做拦截与引导）

| 能力 | 本期规则 |
|---|---|
| 谁看过我 | 非会员 **模糊**，点击 **引导开通会员**；我看过谁默认可完整 |
| 高级筛选 | **部分上锁**，点击引导会员 |
| 无痕浏览 | **仅会员可开**；非会员开开关 → 引导开通会员 |
| 会员套餐页 | 结构本期做；月 / 季 / 年价格可占位 |
| 申请 / 纸飞机额度 | 免费额度用尽可引导会员（与积分并行） |

### 置顶与专业服务

- **置顶：** 本期付费（按天 / 周 / 月，与会员订阅分开）。
- **红娘 / 1v1 / 私人定制：** 本期 **完整在线支付**。

### 积分 / 任务 / 邀请

- 本期 **完整做**：获取 + 兑换（含兑申请次数、纸飞机等可配置项）。

## Content and Voice

### 语气

- 真诚、平等、清楚、有分寸。
- 不居高临下，不制造剩余时间焦虑，不把婚恋结果包装成平台保证。
- 鼓励具体表达，例如共同兴趣、生活节奏和关系期待。

### 推荐表达

- “认真地申请认识”
- “只有双方都愿意，聊天才会开启”
- “合拍度仅供破冰参考，仍要靠真实交流”
- “对方拒绝不会扣除次数”
- “请注意保护隐私与财产安全”
- “喜欢仅自己可见，方便你稍后回来”

### 禁止表达

- “马上脱单”“命中注定”“成功率 100%”
- “最后机会”“仅剩几分钟”“错过就没有”
- 物化、羞辱、婚恋焦虑或以年龄制造恐惧的文案
- 把认证、会员或 AI 描述成绝对可靠的结果保证

## Business Model

### 可接受的收入来源（本期口径）

1. **会员订阅：** 权益门槛与引导本期做；套餐价格可运营占位后上线。权益方向：申请次数、无痕浏览、优先曝光、高级筛选、谁看过我详情、VIP 标识等。
2. **单次增值：** **爆灯 5 元/次**；**置顶** 按档付费；效果边界须在支付前说明。
3. **专业服务：** 红娘牵线、1v1、私人定制等 **本期完整下单支付**。
4. **积分兑换：** 任务 / 邀请获取积分，兑换额度类权益（单价运营配置）。
5. **线下活动（若有）：** 公开活动规则、费用、安全要求和退款条件。

### 商业化硬约束

- 普通用户仍可体验核心价值，不把基础安全能力放到付费墙后。
- 普通用户与会员权益必须并排、完整、可比较。

## AI 画像、搜索与资料合拍参考（ai-policy-2026-08-20-v2）

> 本节取代 `ai-policy-2026-08-07-v1`（一期 text-only + Mock，保留为历史版本，见本节末尾）。裁决依据：[`docs/decisions/2026-08-20-ai-full-feature-baseline.md`](./docs/decisions/2026-08-20-ai-full-feature-baseline.md)。

- who_can_see_me=2 表示查看者 realname_status=2；查看者认证状态缺失或无法判定时拒绝访问（fail-closed）。
- 支持**真实 LLM provider**（DeepSeek，OpenAI 兼容 API）与 Mock provider（开发/测试）。生产环境必须使用真实 provider，禁止生产用 mock。画像抽取、搜索解析由真实 LLM 完成；输出经用户确认后才能发布，认证事实只能来自认证系统。
- 支持**语音 STT/TTS**：STT 用阿里云 NLS paraformer-realtime-v2，TTS 用 cosyvoice-v1。语音功能需独立 `ai_voice_enabled` 门禁（默认 false）；生产启用前必须完成阿里云 SDK 接入、音频存储、音频生命周期（转写后短期保留即删除）、麦克风 consent、阿里云 DPA / 数据出境审查与真机验收。未启用状态 fail closed。
- M03 只编译当前结构化筛选 allowlist，不生成 SQL。allowlist 为 `age`、`city_code`、`marriage_status`、`education_level`、`height_cm`、`income_band`、`occupation_group`、`interest_tags`、`lifestyle_tags`、`relationship_goal`。
- **收入档位 `income_band` 口径（2026-09-03 定义）**：以个人月收入为准，整数 0-6，区间左闭右开（边界值归较高档）：0=无收入/暂不固定，1=5千以下，2=5千-1万，3=1万-2万，4=2万-3万5，5=3万5-5万，6=5万以上。抽取时区间表述（如「一万到两万」）取较低档。
- consent scope：`profile_text_extract`、`search_parse`、`compatibility_shadow`；语音启用后新增 `voice_transcribe`（STT 转写授权）。
- M06 匹配度：一期 shadow 阶段 `display_eligible=false`、算法名 `compatibility-rule-v2`；在真实 LLM 画像数据上 shadow 验证通过 + 安全合规审查后，解冻外显给用户（替换旧 `match_score`/`legacy-rule-v1` 显示）。外显前 legacy 显示保持不变（双读/排空）。
- 生产启用是功能门禁：必须同时具备 `ai_policy_approved`、`ai_provider_approved`、有效 `ai_retention_policy_version`，生产 provider 非 mock，并取得合规批准与 Provider 批准；语音另需 `ai_voice_enabled` 审批。
- 合规、Provider、语音或保留策略未批准，或任一生产启用门禁未满足时返回 HTTP 503 AI_FEATURE_DISABLED（retryable=false）。
- 禁止在生产环境使用 mock provider、无授权 ASR/TTS；向量数据库暂定不引入，本决策不构成其上线授权。
- 普通日志不得写入手机号、身份证、精确位置、原始 IP、原始 prompt、原始 Provider 响应、原始音频、隐藏资料或凭据。

### AI 画像前端体验：墨相（2026-08-22，用户授权文案重设计）

M04「AI 画像」页内体验名为「墨相」（入口不变：`xuanshiai-vue/pagesSub/profileExtra/my-portrait.uvue`）。诗意只放在模块名与两个主体名，按钮、说明、错误与危险操作用白话。产品边界仍以上文 ai-policy 为准：

- **授权接入**：前端接入 GET/PUT/DELETE `/ai/consents`（scope=profile_text_extract，提交服务端冻结版本 `profile-text-v1`，携带 X-Expected-Privacy-Revision）；首次使用展示授权说明页；删除主体画像后端同步撤回授权，前端展示「清理中」。

- **危险操作**：授权、删除、撤回、结束只用产品后果语言，不用墨相隐喻。

## 墨相师实时整理旅程（2026-09-02）

- 画像建构默认通过墨相师对话完成：AI 围绕白名单主题（自我认知、三观与感情观、
  生活方式与作息饮食、物理位置、基本情况）引导用户聊天。每次最终文字或最终语音
  转写都异步抽取为私有高置信候选；聊天回复不等待抽取，语音中间转写不参与抽取。
- 话题边界双层执行：提示词层越界温和拉回；抽取层仅接受白名单字段/分类，
  越界内容不抽取不落库。
- 顶部只展示「墨相整理进度」：六维各按有效高置信候选数计算，0 条为 0%、1 条为
  50%、2 条及以上为 100%；总进度是六维平均。它表达 AI 的理解覆盖度，不代表资料
  已发布；聊天流不展示候选原文。
- **旧协议兼容**：既有邀请门槛和单会话至多 3 次邀请仅服务旧客户端；接受邀请后生成可确认草稿，稍后处理不生成。新主流程不再展示构建邀请，不再逐项点击确认，按下文 `continuous_v2` 执行；任何进度均不能自动发布。
- 知遇按覆盖度感知提问：每轮回复前读取当前会话的整理进度、尚未确认的基础硬字段
  （年龄/所在城市/婚姻/学历/身高/收入/职业）与已沉淀内容，围绕空白处自然追问，
  不复述、不重复追问已确认的信息（2026-09-03 决策）。
- **隐含式引导（2026-09-05，用户确认方向落地）**：自由对话仍是基本盘，不回题库对问；
  知遇对空白维度采用「接话茬钩子」——每维预置两条按主体分池（我的墨相问用户自己、
  愿遇之相问 TA 的期待）的自然切入句式，只在话题接得上时轻轻带出、每轮最多一个方向，
  绝不向用户提及维度名、进度或画像字眼。开场与对话早期只从轻松日常正向的入口起手
  （4 套场景化开场白轮换），亲密模式、关系边界等近身面向等对话有来有回后再自然带出
  （渐进式自我披露）。抽取端配套：内隐线索（情绪/边界/期待藏在生活叙述里）必收，

## 记忆内核核心 v1（2026-09-05）

- **明确延期项**（本期不实现，只保留架构边界）：Search / Compatibility /

## 知遇连续对话与双画像（2026-10-08，已批准）

本节是新主流程 `continuous_v2` 的现行口径，覆盖历史段落的先个人后偏好、构建邀请、逐条确认与字段数量发布门槛；旧协议保留一个兼容周期。知遇是理解用户、形成画像和改善择偶推荐的统一入口，不是独立的长期情感陪伴产品，亦非浏览人的前置门槛。纸飞机、认证和双方同意后聊天规则不变。

- 一段对话后台整理 `personal`（我的真实画像）和 `ideal_partner`（期待的长期关系）；同一句可有两组明确证据，不建立第三方画像。否定、引用、不确定和矛盾表达先澄清，不把推测当成事实。
- 下次进入沿用当前授权允许的已确认画像、有效历史和待核对信息；增量修订保留未改变内容。资料读取失败不能冒充资料为空，确认一份不得清空另一份。
- 两份独立呈现整理中、生成中、待确认、已确认，以及失败/重试/过期状态。覆盖度来自有效证据；生成状态来自真实任务，不使用计时假进度。
- 首次自动成稿：至少 3 个有效维度、3 条达到现有高置信标准且有来源的证据，无必须先澄清的底线冲突；不要求固定轮数或另一份完成。已有正式稿只需有效增量即可生成更新稿。完整成稿是可完整阅读的结果，不代表所有未知信息被填满。
- 同一内容版本只生成一次，待确认稿冻结；继续聊天产生的信息另行提示合并，不覆盖正在阅读的内容。失败或中断后可恢复任务与稿件。
- 用户阅读完整叙事及将生效的结构化信息，支持修改，再整份确认；后续更新突出差异，底线变化单独提醒。不用自动全选旧字段代替真实审阅。
- 正式版本必须与用户审阅的预览和字段版本一致；幂等确认、并发冲突、授权与旧接口绕过由服务端校验。确认后不再另生成未经审阅的正式正文。
- 生成不等于正式确认，正式确认不等于公开展示。本人可见心理推断、对方私密偏好与原始对话不进入公开资料。自己的正式画像按既有可见性规则进入「我的」与海报。
- 确认后依既有授权更新推荐/搜索投影，不修改认证事实、不覆盖已填基础资料；既有行为学习不能静默修改正式画像或放宽明确底线。撤回/删除使任务写回与下游消费失效。
- 外部入口、内部对话和等待状态统一复用现有小猫知遇 IP；延续所属页面 Token 和既有海报品牌，不混用另一套人物立绘。
