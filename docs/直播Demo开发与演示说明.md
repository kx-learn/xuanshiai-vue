## 1. 交付与边界

现有六个直播页面支持显式 `mode=demo`：场次准备、预约确认、签到候场、四轮互动、本人结果、自主申请、接收方答复与双方同意后聊天。一个人切换角色，手动推进和跳过等待，建议讲解 5—10 分钟。

Demo 使用虚构人员和文字头像。它不请求直播凭证、不连接 HTTP 业务接口或实时服务、不挂载原生音视频组件、不申请摄像头与麦克风权限，不写登录身份、正式申请、聊天或日常额度。设备检查仅模拟流程。

不带 `mode=demo` 的原入口继续调用 `api/live-v2.uts`，不会因为请求失败自动进入演示。全局 `USE_MOCK`、账号、父母端身份均不改变。真实云平台、后端、数据库、GitHub，以及 `pages.json`、`manifest.json` 均不在本次修改范围。

## 2. 快速启动

### 2.1 编译正确的项目

在 HBuilderX 中选择 `D:/项目/宣誓爱/xuanshiai-vue`，运行到微信开发者工具。不要运行外层 `D:/项目/宣誓爱` 的历史工程。

本机可用的 PowerShell 命令：

```powershell
Set-Location 'D:/项目/宣誓爱/xuanshiai-vue'
& 'D:/HBuilderX/cli.exe' launch mp-weixin --project xuanshiai-vue --compile true
```

微信开发者工具打开：`D:/项目/宣誓爱/xuanshiai-vue/unpackage/dist/dev/mp-weixin`。本工程使用 HBuilderX 构建路线，不能把 npm CLI 的输入目录问题当成页面已编译成功。

### 2.2 设置自定义编译模式

在微信开发者工具顶部的编译模式下拉中，新增：

| 字段 | 填写内容 |
| --- | --- |
| 模式名称 | 直播 Demo |
| 启动页面 | `pagesSub/live/lobby` |
| 启动参数 | `mode=demo` |

点击编译。页面顶部应出现“演示模式 · 虚构人物”，默认身份是“男一 · 林屿”。其他直播页面可以直接用 `id=1&mode=demo` 启动，但建议从大厅完整讲解。没有演示标识时不要继续操作；先核对编译产物与参数。

后端可以关闭，不需要配置腾讯云凭证。Demo 不需要伪造登录。明确进入这六个 Demo 页面时，应用入口不会执行开发登录，也不会被父母端身份分流带走；此例外不适用于其他页面。

### 2.3 重置、退出与保存

- 点击“演示控制”展开，点击“重新开始”并确认，回到初始大厅。
- 数据仅在本次小程序运行内存中跨页共享。关闭并重新启动模拟器会恢复初始状态；同一进程内仅重新进入页面可能保留进度，确定重演请使用“重新开始”。
- 切换角色不会改变真实账号；会清除选择草稿、申请与聊天弹层、输入草稿，并回到“收到的申请”标签。
- 回到普通业务入口即使用原有业务链。向甲方展示时建议一直使用面板内的大厅、场次管理、直播间、场后结果导航。

## 4. 5—10 分钟演示脚本

演示前先重置。讲解时每完成一次操作，等待界面确认。下文“推进”指面板里的“切至控场者并推进”；需要结束选择或一组交流时，先点“跳过当前等待”，再推进。不要先跳过选择时间再载入预设。

### 4.1 场前：约 1 分钟

1. 可先点“切至运营管理”，查看“小程序场次管理”和“固定演示名单”。标题和时间可编辑；“保存演示草稿”会重置本场并进入房间，由独立运营“确认排期”。不创建真实账号或场次；主持不能创建、排期或取消。只讲流程可使用初始排期场次。
2. 切到“男一 · 林屿”，在大厅点“查看场次”。点“预约观看本场”，文案变为“取消观看预约”。说明观看预约与嘉宾资格分别记录。
3. 查看虚构展示称呼和介绍，勾选告知，点“确认本场参与身份”。成功后按钮变为“更新本场授权资料”。
4. 点“签到与设备检测”，在候场页点“完成模拟设备检查”，看到“模拟检查已完成”后点“确认签到”。点“进入候场直播间”。
5. 展开演示面板，点“模拟全员就绪”，再点“切至控场者并开场”。进入第一轮自我介绍，舞台为一位主嘉宾、四位候选人、三位工作人员，运营不自动上台。

### 4.2 第一轮：完整互动，约 2—3 分钟

1. 自我介绍：查看林屿的授权介绍、候选席和工作人员区。可收起面板观察舞台。
2. 推进到“红娘问答”。切换红娘，点“举手申请提问”，可撤回并显示等待状态；或切换候选嘉宾，点“举手申请发言”。候场嘉宾不能举手。切回主持，在“工作人员界面”展开“查看名单与人员操作”，对允许的上台者点“请TA发言”。这里只模拟发言状态。
3. 推进到“亮灯”。切到男一，向女一点“为TA亮灯”，再点“撤回亮灯”；点“特别心动（免费）”，再点“撤回特别心动”。特别心动次数已使用，其他特别心动按钮不可再用。说明亮灯不绑定最终选择。
4. 推进到“私密选择”。切到男一，选择女一、女二、女三，点“提交我的选择（3 人）”。截止前可以取消一个选项再提交，也可以再选回来；标准脚本最终保留这三人。
5. 切到女一，点“愿意与主嘉宾交流”。切到主持、红娘或观众，确认没有别人的单方选择列表。
6. 点“载入本轮其他人意愿”，补齐女二、女三等尚未提交者。然后“跳过当前等待”并推进，只公布三组互选队列，依女一、女二、女三席位顺序。
7. 每一组交流都先跳过等待再推进，共三次，分别完成三组交流。可中途“暂停流程”，展示时间保留，再“恢复流程”；暂停不改变组合顺序。
8. 到“轮换”后再推进，进入第二轮。普通亮灯清空，特别心动已用次数不会恢复。

### 4.3 第二轮：无人互选，约 30 秒

1. 主嘉宾为女一。依次推进自我介绍、红娘问答、亮灯，进入私密选择。
2. 不手动提交本轮意愿，直接“载入本轮其他人意愿”。本轮预设为女一选择男二，男嘉宾均暂不交流。
3. 跳过等待并推进，显示“本轮没有互选组合”，不出现替代配对，也不公开单方名单。
4. 推进到第三轮。

### 4.4 第三轮：交流退出，约 1 分钟

1. 主嘉宾为男二。进入私密选择，载入本轮预设，跳过等待并推进。
2. 队列有男二—女一、男二—女四。第一组跳过等待并推进，标为“已完成”。
3. 切到女四，在第二组交流中点“退出本轮交流”并确认。该组标为“已退出”，不产生场后机会。
4. 推进到第四轮。退出的是本轮交流，不等同于退出整个场次。

### 4.5 第四轮：去重与结束，约 30 秒

1. 主嘉宾为女二。进入私密选择，载入本轮预设，跳过等待并推进。
2. 预设中女二与男一、男三互选。男一—女二已在第一轮完成交流，因此队列只有男三；特别心动也不能改变去重或顺序。
3. 跳过等待并推进，完成新组合；再推进完成四轮，最后点击“切至控场者并结束”。只有结束场次后才发放专属机会。

### 4.6 场后：自主申请、同意与拒绝，约 1—2 分钟

1. 切回男一，进入“场后结果”。标准脚本下有女一、女二、女三三份机会；每份由双方共享，不是两边各一次。
2. 对女一点“自主申请认识”，可修改申请说明，再点“确认发送演示申请”。查看“发出的申请”，状态等待答复，没有聊天入口。
3. 关闭弹层，切到女一，点“查看演示申请与答复”，在“收到的申请”点“同意”。出现“打开演示聊天”。输入内容后点“发送演示消息”。
4. 关闭聊天，切回男一并打开演示聊天，可以看到同一条消息并回复。这些消息只保存在本次本机内存中。
5. 男一另向女二自主申请；切到女二，在收到的申请中点“拒绝”。状态为“已婉拒”，不显示聊天入口，已使用机会不恢复，日常额度不增减。
6. 切到男二验证只有女一的机会；与退出交流的女四没有机会。观众、主持与红娘没有嘉宾场后机会。

如果手动选择改变了标准组合，后面的结果会随真实本地状态改变。不要用预设强行覆盖操作者的选择；需要讲解标准结局时重新开始。

## 5. 规则与角色边界

| 能力 | 规则 |
| --- | --- |
| 普通亮灯 | 仅当前主嘉宾与候选人，公开、可撤回、每轮重置；不绑定最终选择 |
| 特别心动 | 每人每场一次，免费，可撤回但不恢复次数，不改变交流顺序 |
| 私密选择 | 主嘉宾选 0—3 个有效候选人；候选人独立表态；截止前可修改 |
| 隐私 | 每份快照只带 `me.selection`；成员公开资料不含选择。主持、红娘、观众也看不到未互选意愿 |
| 交流 | 按候选席位顺序；无互选直接轮换；退出不发机会；已完成的双方本场不重复安排 |
| 场后机会 | 完成交流后、场次结束时生成，每对共享一次，结束后 72 小时内有效；不自动发送申请 |
| 答复 | 当前既有规则为发送后 48 小时；只有接收方可以答复；过期不能补答 |
| 聊天 | 仅明确同意后开放；未答复、拒绝、过期均不可聊天 |
| 运营 | 独立创建／排期／取消、名单、接管／交还及处置；不能代选择，不自动上台 |
| 主持 | 拥有控场权时开场、环节控制、发言、模拟上下台；不能移出运营，不能代选择 |
| 红娘 | 问答阶段申请／撤回提问和等待安排，查看授权资料，不代亮灯或代选择 |
| 观众 | 观看与举报；演示面板切换身份不等于观众业务权限 |

普通时长仍是介绍 180 秒、问答 240 秒、亮灯 60 秒、选择 60 秒、每组交流 120 秒、轮换 60 秒。面板跳过等待仅改变本地时间偏移；不会修改正式规则。倒计时不会自动推进，环节推进由命令确认。

## 6. 实现与维护

### 6.1 文件分工

| 文件 | 职责 |
| --- | --- |
| `pagesSub/live/client.uts` | 轻量 `LiveClient`；显式选择真实 API 或本地实现；统一页面间 URL |
| `pagesSub/live/demo.uts` | 私有本地状态、角色快照、四轮命令、时钟、预设、机会、申请和演示消息 |
| `pagesSub/live/LiveDemoPanel.uvue` | 控制面板、角色切换、预设、跳过、重置与分包内导航 |
| `pagesSub/live/LiveDemoStage.uvue` | 主嘉宾、候选席、文字头像和紧凑工作人员区 |
| `pagesSub/live/LiveDemoFollowUp.uvue` | 场后机会、申请答复、聊天；复用无数据服务副作用的 `XsaSheet`、`XsaApplicationTabs` |
| `pagesSub/live/LiveRoundActions.uvue` | 复用的嘉宾动作；身份、轮次或本人已提交选择变化时刷新草稿 |
| `pagesSub/live/LiveStaffPanel.uvue` | 复用的工作人员动作，Demo 默认收起名单 |
| `pagesSub/live/{lobby,detail,backstage,room,results,manage}.uvue` | 现有六页接入调用边界、传递 Demo 参数 |
| `utils/liveDemoRoute.uts`、`App.uvue` | 六页精确白名单，仅明确 Demo 冷启动跳过开发登录与父母端分流 |

沿用 `api/live-v2.uts` 的 `LiveSnapshot`、`LiveCommand`、`LiveCreate` 等类型。离线Demo不依赖后端；2026-09-27真实业务扩展的名单、控场与媒体模式字段也已对齐本地模型。真实／演示通过明确适配器隔开，不在请求失败后静默伪造成功。

本地状态不是持久缓存。页面订阅变化，卸载时取消订阅。房间保留本地倒计时，不启动真实订阅或轮询。命令带编号与版本，重复命令不会重复执行，旧版本明确报错；业务必要的权限、截止和共享机会校验保留，不额外搭建重试或兼容框架。

预设直接调用与手动操作相同的命令规则，只补未提交者。所有意愿集中在状态模块的私有轮次结构；`demoSnapshot()` 用公开字段构造角色视图，不把私密数据发给页面再隐藏。

场后申请与聊天不复用带真实接口副作用的消息中心或申请服务，只复用展示组件。共享机会中保存一份申请，因此重复点击或双方先后发起取得同一有效申请。该单进程行为不是数据库并发事务验收。

### 6.2 常见维护问题

- 只修改了源码但界面没变：确认选中生产子项目、HBuilderX 编译成功、开发者工具打开最新产物。
- 微信布局横排变成竖排：UniApp x 的默认布局不能照搬普通网站；对横向区域明确写 `flex-direction: row`。
- 自动化找不到 XsaButton 的可点击区域：组件可能是 `virtualHost`，需通过组件定位其内部原生 `button`，不要点击零尺寸组件宿主。
- 更换角色后收到的申请不见了：核对 `LiveDemoFollowUp.refresh()` 重置标签、草稿与弹层，不以延时或强制刷新绕过角色状态问题。
- 选择阶段预设无效：检查是否已截止、是否手动提交过；预设不会覆盖已提交选择。
- 模拟器响应超时：检查微信 IDE 是否仍打开、重新用 CLI 开启自动化。截图失败与业务断言通过分别记录，不增加业务重试掩盖工具问题。
